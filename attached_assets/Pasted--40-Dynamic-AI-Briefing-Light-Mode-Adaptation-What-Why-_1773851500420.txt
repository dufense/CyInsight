#40 - Dynamic AI Briefing & Light Mode Adaptation
What & Why
The Executive Intelligence Briefing has two problems:

The narrative text is a static template string assembled from sub-function outputs — it does not call OpenAI to produce a truly contextual, adaptive security narrative. The text doesn't change meaningfully between sessions or adapt to emerging threats.
The component (executive-briefing.tsx) uses hardcoded dark HSL colors and white/X opacity utilities that look broken in light mode — dark navy backgrounds over a light page.
Done looks like
The AI narrative in the briefing changes dynamically based on real incident count, severity mix, top MITRE tactics, SLA health, event volume, IOC count, and week-over-week trends. Two tenants with different security postures get visibly different briefings.
The "Situation" and "Key Findings" sections are generated by OpenAI (gpt-4o-mini) with a rich system prompt containing live metric context — not static template strings.
The briefing component renders correctly in both light and dark mode: light mode uses a slate-100 background, dark text, visible borders, and colored accents without any dark-only overrides.
A graceful fallback is still shown if AI is unavailable (rate-limited or errored).
Out of scope
Changing the gauge SVG layout or KPI strip structure
Adding new data sources beyond what the briefing endpoint already queries
Tasks
AI-powered briefing narrative — Update getDailyBriefing in aria-copilot.ts to call OpenAI with a structured system prompt containing live incident counts, severity breakdown, top MITRE tactics, MTTR, SLA health, event volume, and week-over-week delta. Return a structured JSON response with situation (2-3 sentence narrative paragraph) and keyFindings (3-5 concise bullet points), both specific to the current data.

Update briefing API response — In routes.ts at /api/dashboard/briefing, use the newly structured getDailyBriefing output to populate sections.situation and sections.keyFindings rather than the current template concatenation. Ensure the fallback still works when AI is unavailable.

Light mode adaptation for ExecutiveBriefing — Update executive-briefing.tsx to read the dark/light mode via a useEffect watching document.documentElement.classList. In light mode, replace the dark navy gradient with a clean slate/white card, use text-foreground / text-muted-foreground for text, and remove white/X opacity utilities (replace with border, text-muted-foreground, bg-muted/30 semantics). The gauge SVG must also work on a light background.
