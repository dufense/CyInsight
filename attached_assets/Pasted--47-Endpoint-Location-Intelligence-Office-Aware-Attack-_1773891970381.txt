#47 - Endpoint Location Intelligence: Office-Aware Attack Map
Problem
The world map currently draws all attack arcs to a hardcoded to: "US" target, regardless of which tenant office was actually attacked. For PKF Africa — with offices in Nairobi, Mombasa, Kampala, Kigali, Dar es Salaam, Nakuru, Malindi — every attack arc goes to the wrong place. We need geo-intelligence to route arcs to the correct physical office location.

What & Why
Two intelligence signals to exploit
Signal 1 — Hostname prefix (immediate intelligence) The platform already has mappings for PKF hostnames in routes.ts:

NRB, NBI → Nairobi, Kenya   (lat: -1.286, lon: 36.817)  *note: Nairobi is just south of equator
KLA       → Kampala, Uganda  (lat: 0.347,  lon: 32.582)
MSA       → Mombasa, Kenya   (lat: -4.043, lon: 39.668)
KGL       → Kigali, Rwanda   (lat: -1.943, lon: 30.062)
DAR, TZ   → Dar es Salaam, Tanzania (lat: -6.792, lon: 39.208)
NKR       → Nakuru, Kenya    (lat: -0.303, lon: 36.080)
MLD       → Malindi, Kenya   (lat: -3.214, lon: 40.117)
PKF hostnames: PKFMSA-JOO2 → MSA → Mombasa; mwesigwad-kla → kla → Kampala; C37R-NRB → NRB → Nairobi. Extract the prefix from asset or target field, map to office location.

Signal 2 — IP range matching (deeper intelligence)
infrastructure_locations table has privateIpRanges (JSONB, array of CIDR strings). When an endpoint event carries a private IP in its asset/target field, match it against stored CIDRs to identify which office subnet it belongs to.

Schema change
Add city (varchar 100), countryCode (varchar 5), latitude (real), longitude (real), hostnameKeywords (text[]) to infrastructure_locations. These fields are nullable so no existing rows break.

Seeding office locations

hostnameKeywords arrays (e.g. ["NRB","NBI","PKFNRB"] for Nairobi)
Approximate private IP ranges per office

API changes
Enhance /api/threat-map/arcs: For each event row, apply location intelligence:

Extract hostname-style prefix from asset field using regex (/(?:^|[-_])([A-Z]{2,5})(?:[-_\d]|$)/i)
Look up matching office from tenant's infrastructure_locations via hostnameKeywords
If no hostname match, check if asset/target field is a private IP — match against privateIpRanges CIDRs using subnet math
If still no match, use tenant's primary office (first seeded location, or HQ)
Set toLat, toLon, toCity, toCountry on each arc group
New endpoint GET /api/threat-map/offices?tenantId=X: Returns all infrastructure_locations for the tenant that have lat/lon set: { id, name, city, countryCode, lat, lon, hostnameKeywords }[] Used by the frontend to render persistent office markers on the map.

Frontend changes
ArcData type — add optional fields:

interface ArcData {
  from: string;    // ISO2 attacker country
  to: string;      // ISO2 defender country (for country fill color)
  severity: string;
  count: number;
  toLat?: number;  // precise target lat when known
  toLon?: number;  // precise target lon when known
  toCity?: string; // city label
}

Add OfficeMarkers inner component: renders a distinct marker for each office (blue pulsing ring + inner dot + city label on hover), separate from the generic "Protected Network" US dot
